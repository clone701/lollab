# 要件定義書: 試合詳細

## はじめに

サモナー検索の対戦履歴で、試合カードの展開ボタン（▼）を押すと、その試合の詳細をカードの下に展開して表示する。
試合に参加した10人の成績とチームの結果、各プレイヤーのビルド（アイテムの購入順・スキルの上げ順・ルーン）を、別の画面に移らずに確認できるようにする。

## 用語集

- **試合詳細**: 1試合分の、参加者10人の成績・チームの結果・ビルドをまとめた表示
- **対象プレイヤー**: 検索したサモナー
- **KDA の比率**: (キル + アシスト) / デス。デスが0なら「Perfect」
- **キル関与率**: (キル + アシスト) / チームの合計キル。チームの合計キルが0なら0%
- **オブジェクト**: ドラゴン・バロン・リフトヘラルド・ヴォイドグラブ・タワー・インヒビター
- **生データ**: 保存済みの Riot API の試合詳細とタイムラインの JSON

---

## 要件

### 要件1: 展開と折りたたみ

**ユーザーストーリー:** プレイヤーとして、気になる試合だけ詳しく見たい。そうすることで、対戦履歴の一覧を見失わずに振り返れる。

#### 受け入れ基準

1. WHEN ユーザーが試合カードの展開ボタンを押した場合、システムはそのカードの下に試合詳細を表示する
2. WHEN ユーザーが展開中の試合カードの展開ボタンを押した場合、システムは試合詳細を閉じる
3. 展開ボタンは、展開中と閉じているときで向きが変わる
4. 複数の試合を同時に展開できる
5. WHILE 試合詳細を読み込んでいる間、システムは読み込み中であることを表示する
6. 一度読み込んだ試合詳細は、閉じて開き直したときに読み込み直さない（同じ画面を開いている間）

### 要件2: 概要タブ

**ユーザーストーリー:** プレイヤーとして、試合に参加した全員の成績を比べたい。そうすることで、試合の流れと自分の貢献を把握できる。

#### 受け入れ基準

1. 試合詳細は「概要」と「ビルド」のタブを持ち、初期表示は「概要」とする
2. 概要は、勝利チームと敗北チームに分けて各5人を表示し、チームごとに勝敗とチームの色（ブルー・レッド）を示す
3. 各プレイヤーについて、チャンピオン・チャンピオンレベル・サモナースペル・メインとサブのルーン・名前・KDA（キル/デス/アシスト）とその横にキル関与率・KDA の比率・与ダメージ・受けたダメージ・コントロールワードの購入数とワードの設置数・破壊数（カーソルを合わせると内訳を表示）・CS と分あたりの CS・最終アイテムを表示する
4. 与ダメージと受けたダメージは、試合内の最大値に対する割合を棒で示す
5. 対象プレイヤーの行は他の行と区別して表示する
6. 両チームの合計キルと合計ゴールドを、比較できる形で表示する
7. 両チームのオブジェクトの獲得数を表示する
8. WHERE プレイヤーのランクが分かっている場合、名前の近くにランクを表示する。分からない場合は表示しない
9. WHEN ユーザーがプレイヤーの名前を押した場合、システムはそのプレイヤーのサモナー検索結果のページへ移る
10. WHEN ユーザーがチャンピオンのアイコンを押した場合、システムはそのチャンピオンのビルドページへ、そのプレイヤーのロールを選んだ状態で移る

### 要件3: ビルドタブ

**ユーザーストーリー:** プレイヤーとして、試合中に何をどの順で選んだかを見たい。そうすることで、ビルドの判断を振り返れる。

#### 受け入れ基準

1. ビルドタブは、初期表示で対象プレイヤーのビルドを表示し、ほかの9人に切り替えられる
2. アイテムの購入順を、購入した時刻（分）ごとにまとめて時刻順に表示する。購入を取り消したアイテムは表示しない（売却したアイテムは購入時点の表示に残す）
3. スキルの上げ順を、レベルごとに表示し、最大まで上げた順（例: Q > W > E）も表示する
4. ルーンは、メインとサブのツリーの全ルーンとステータスシャードを並べ、選んだものを強調して表示する

### 要件4: データの取得

**ユーザーストーリー:** 運営者として、試合詳細を費用をかけずに、Riot API の利用を増やさずに表示したい。そうすることで、検索やクローラーの利用量を圧迫しない。

#### 受け入れ基準

1. システムは、保存済みの生データから試合詳細を作り、Riot API を呼ばない
2. IF 生データが見つからない場合、システムは Riot API から試合詳細とタイムラインを取得し、生データとして保存してから表示する
3. IF タイムラインが取得できない場合、システムは概要を表示し、ビルドタブのうちアイテムの購入順とスキルの上げ順は「データなし」と表示する
4. 他の参加者のランクを調べるために Riot API を呼ばない
5. IF 試合詳細を取得できない場合、システムは試合詳細の場所にエラーを表示し、再試行できるようにする
6. 試合詳細の表示は3秒以内に返す（生データがある場合）

### 要件5: アクセス制限

#### 受け入れ基準

1. 試合詳細の取得は、サモナー検索の API と同じアクセス制限（ログインと許可メール）を受ける
2. 試合 ID の形式が不正な場合、システムは取得を拒否する

### 要件6: 範囲外

- 自前のスコア（OP スコア相当）・順位・MVP・推移のグラフ
- チーム分析・その他のタブ
- ランクが分からない参加者のランクの取得
- 試合詳細の単独のページ（URL での共有）
