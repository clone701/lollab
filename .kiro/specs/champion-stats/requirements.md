# 要件定義書: チャンピオンビルド

## はじめに

ヘッダーの「チャンピオン」タブから、チャンピオンを検索してロール別のビルド（LoLalytics の Build 相当）を表示する。
統計は DB に保存済みのランク戦の試合（サモナー検索・更新・Backfill と、クローラーで集まった試合の参加者10人分）から集計する。

## 用語集

- **対象試合**: DB に保存済みのランク戦（ソロ/デュオ・フレックス）の試合
- **ロール**: TOP / JUNGLE / MIDDLE / BOTTOM / UTILITY
- **ビルド要素**: スキル優先順・スキル順・サモナースペル・開始アイテム・コアビルド・4〜6番目のアイテム・ルーン・ステータスシャード
- **最多ビルド**: ビルド要素ごとに試合数が最も多い選択肢
- **採用率**: 選択肢の試合数 / その要素の集計対象の試合数
- **集計期間**: 最新パッチ・直近30日・全期間のいずれか

---

## 要件

### 要件1: チャンピオン検索

**ユーザーストーリー:** プレイヤーとして、調べたいチャンピオンをすぐに開きたい。そうすることで、試合前に素早くビルドを確認できる。

#### 受け入れ基準

1. ヘッダーの「チャンピオン」タブは、チャンピオン検索画面を開く
2. 検索画面はチャンピオンをアイコン付きで一覧表示する
3. WHEN ユーザーがチャンピオン名を入力した場合、一覧は名前が一致するチャンピオンだけを表示する（日本語名・英語名の両方で検索できる）
4. WHEN ユーザーがチャンピオンを選んだ場合、そのチャンピオンのビルド画面を表示する

### 要件2: ビルド画面の概要

**ユーザーストーリー:** プレイヤーとして、チャンピオンの強さをロール別に把握したい。そうすることで、そのチャンピオンを使うか判断できる。

#### 受け入れ基準

1. ビルド画面は勝率・全体平均勝率との差・ピック率・BAN率・試合数を表示する
2. ビルド画面はロールを切り替えられ、初期表示はそのチャンピオンの試合数が最も多いロールとする
3. ビルド画面の URL はチャンピオンとロールを含み、共有・再訪問できる

### 要件3: ビルド

**ユーザーストーリー:** プレイヤーとして、勝てるビルドとよく使われるビルドを知りたい。そうすることで、試合前の準備に使える。

#### 受け入れ基準

1. ビルド画面は最多ビルドを表示する（最高勝率ビルドは試合数の少ない選択肢が選ばれやすいため廃止。#142）
2. 各ビルド要素は、選択肢・勝率・試合数を表示する
3. スキルはスキル優先順（Q/W/E の最大化順）とレベル1〜15のスキル順を表示する（LoLalytics と同じ。15レベル以降は試合時間が短いと到達しないため）
4. アイテムは開始アイテム・コアビルド（最初に完成させた3つ、購入順）・4〜6番目の候補をそれぞれ表示する
5. ルーンはメイン（キーストーン含む4つ）・サブ（2つ）・ステータスシャード（3つ）を表示する
6. WHEN ビルド要素の集計対象の試合が0件の場合、その要素は「データなし」と表示する
7. サモナースペルは、試合数が最も多い選択肢と2番目の選択肢を2行で表示し、それぞれに採用率を横棒で表示する
8. ルーンは、試合数が最も多い選択肢と2番目の選択肢を「1番目」「2番目」のボタンで切り替えて表示する。ボタンには採用率を表示し、初期表示は1番目とする。2番目が無ければボタンは出さない

### 要件4: 絞り込み

#### 受け入れ基準

1. ビルド画面は集計期間をボタンで切り替えられ、初期表示は最新パッチとする
2. ビルド画面はキュー（すべて・ソロ/デュオ・フレックス）をボタンで切り替えて絞り込める
3. ビルド画面はランク帯（すべて・エメラルド以上・ダイヤモンド以上・マスター以上）で絞り込める。初期表示は「すべて」とする
4. ランク帯を「すべて」以外にした場合、ランク帯を持つ試合（クローラーが集めた試合）だけを集計する
5. ビルド画面は集計対象の試合数を表示する
6. 試合数による足切りは行わない。信頼性の判断は表示された試合数をもとにユーザーに委ねる
7. 期間・キュー・ランク帯・ロールと、勝率などの概要の値は、基礎情報の下の「ビルドの集計」カードにまとめて表示する（基礎情報は絞り込みで変わらないため、絞り込みはそれより下に置く）

### 要件5: 性能

#### 受け入れ基準

1. ビルド画面の表示は3秒以内に返す
2. 統計の集計は Riot API を呼ばず、DB のデータだけで行う

### 要件6: 範囲外

- ティアリスト（ティア・順位を含む）、カウンター（別 Spec で追加予定。必要なデータは本 Spec の対応で保存済みになる）
- リーダーボード、プロビルド
- 試合を自動で集める仕組み（match-crawler Spec）
- 試合詳細画面（サモナー検索の別 Spec。必要なデータは summoner-search-api 要件4で保存する）
