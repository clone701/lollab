# 要件定義: skill-values

## 概要

スキルのツールチップに、ランクごとの数値が入った日本語の説明文を出す（例: アーゴット Q「榴弾を発射して 25/70/115/160/205 (+攻撃力の70%) の物理ダメージを与え、1.25秒間 45/50/55/60/65% のスロウ効果を与える」）。Issue #132。game-data-tooltip（#128）の続き。

## 前提

- 説明文は Data Dragon（ja_JP）の `tooltip` を使う。`{{ totaldamage }}` のような値は、CommunityDragon のゲームデータ（`game/data/characters/<名前>/<名前>.bin.json` の `DataValues`・`mSpellCalculations`）から計算して入れる
- CommunityDragon は Data Dragon と同じ版（今は 16.21）のフォルダを使う
- 計算はスクリプトで行い、結果のファイルをリポジトリに置く（ブラウザでは計算しない）
- 調査（16.21、173体）: スキルの `{{ }}` 2,672個のうち 2,463個（92%）は、名前が一致し、知っている種類の計算だけでできている
- CommunityDragon の日本語の文字列ファイル（36MB）はスクリプトの中でだけ使い、リポジトリには置かない

## 範囲外

- レベルやスタックで変わる値の、特定の時点の値（例: 「レベル11で」）。レベルで変わる値は最小〜最大の範囲で出す（要件2.5.3。スキルも同じ）
- アイテム・ルーンの説明文（Data Dragon の時点で数値が入っている）
- 英語など日本語以外

## 要件

### 要件1: 数値入りの説明文

**ユーザーストーリー:** ビルドを見ているプレイヤーとして、スキルの強さを数値で知りたい。

1. スキルのツールチップの説明文を、`tooltip` の `{{ }}` に値を入れたものにする
2. ランクで変わる値は、ランク1〜最大ランクの値を `/` でつなぐ（例: `25/70/115/160/205`）。全ランクで同じ値は1つだけ出す（例: `1.25`）
3. ステータスで増える分は、値の後ろに括弧で出す（例: `25/70/115/160/205 (+攻撃力の70%)`）。ステータスの名前は日本語にする（攻撃力・増加攻撃力・魔力・最大体力・増加体力 など）
4. `{{ slowamount*100 }}` のような掛け算・割り算を計算する
5. 小数は最大2桁で、末尾の0は付けない（例: `0.45` → `45`（*100 のとき）、`9.5`）
6. 色付けのタグ（`<physicalDamage>` など）は今のまま使い、game-data-tooltip の色分けがそのまま効く

### 要件2: 解けないときの扱い

1. スキルの中に1つでも計算できない `{{ }}` があれば、そのスキルは今の概要（`description`）を出す（`?` や空欄を出さない）
2. `{{ spellmodifierdescriptionappend }}` のような説明の付け足しの値は、取り除いて解けたものとして扱う

### 要件2.5: パッシブ

1. パッシブも数値入りの説明文にする（例: アーゴット「…<physicalDamage>@ADDamage@(+最大体力の@PercentHPRatio@)の物理ダメージ</physicalDamage>…脚ごとに@PerLegCD@秒間のクールダウン…」に値を入れる）
2. Data Dragon のパッシブには値の入る説明文が無いため、CommunityDragon の日本語の文字列（`game/ja_jp/data/menu/en_us/lol.stringtable.json` の `spell_<名前>passive_tooltip` など）と、パッシブのスペルの計算（`<名前>PassiveAbility`）を使う
3. パッシブの値はチャンピオンのレベルで変わるものが多い。レベルで変わる値は、レベル1の値とレベル18の値を `〜` でつなぐ（例: `20〜100`、短くなるクールダウンは `30〜2.5`）
4. 文中の `{{Spell_UrgotW_Name}}` のような他の文字列の参照は、その文字列（スキル名など）に置き換える
5. パッシブのスペル・文が見つからないとき、または解けないときは、文字列表の `game_character_passivedescription_<名前>`（数値が入った文）を使う。それも無いか値が残るときは概要を出す

### 要件2.6: 書き方の追加

1. % の値にステータスで増える分が付くときは「25% (+魔力100ごとに4%)」と書く
2. スタックで増える値は「1スタックにつき X」と書く
3. 文の中のアイコンの記号（`%i:scaleAS%` など）は取り除く
4. 古い形式の `@EffectNAmount@`（N は 1〜11）は、スペルの `mEffectAmount[N-1].value` のランクごとの値で入れる（`value[0]` は使わない）。全ランク 0 のときは解けない扱い
5. `f1` などの名前と、クリティカルダメージ・現在の体力・失った体力で増える値は対応しない（そのスキルは概要）

### 要件3: 生成スクリプト

1. Data Dragon の版のフォルダ（例: `D:\dev\16.21.1`）を引数に取り、CommunityDragon の同じ版のデータを取得して、チャンピオンごとの結果のファイルを書き出す
2. 結果のファイルには、スキルごとに数値入りの説明文か「解けなかった」ことだけを入れる（CommunityDragon の元データは置かない）
3. 実行の最後に、解けたスキルの数と割合、解けなかった `{{ }}` の上位を表示する
4. 同じ入力で何度流しても同じ結果になる（差分を `git diff` で確かめられるように、並び順・数値の書き方を固定する）
5. 手順（ダウンロード → スクリプト → `git diff` で確認 → 公式のパッチノートと見比べる → コミット）を docs か steering に書く

### 要件4: 画面

1. 数値入りの説明文は、チャンピオン1体分のファイルを、スキル画像と同じときに読み込む（ビルド画面・試合詳細のビルドタブを開いたとき。基礎情報で使うため）
2. 読み込み中・失敗は今の概要を出す
3. ビルド画面・試合詳細のビルドタブの、スキルのツールチップすべてに出す

### 要件5: 品質

1. 計算が正しいことを、いくつかのスキルで実際のゲームの値と見比べて確かめる（アーゴット Q・E、アーリ Q、ジンクス W など。テストに入れる）
2. 解けるスキルの割合を 80% 以上にする（解けない理由を見て、多いものから対応する）

### 要件6: ビルド画面の基礎情報

**ユーザーストーリー:** ビルドを見ているプレイヤーとして、チャンピオンの基本の強さとスキルの効果を同じ画面で確かめたい。

1. ビルド画面のチャンピオン名の下（ロールのタブの上）に「基礎情報」のカードを出す
2. チャンピオン名の横に称号（例: ドレッドノート）と役割（`tags` を日本語にする: ファイター・タンク・メイジ・アサシン・マークスマン・サポート）を出す
3. 特性: 攻撃・防御・魔力・難易度（Data Dragon の `info`、0〜10）を横棒で出す
4. ステータス: 体力・リソース・物理防御・魔法防御・移動速度・攻撃力・攻撃速度・体力自動回復・リソース自動回復・射程を、Lv.1・成長（レベルごとの増加）・Lv.18 の表で出す
   - リソースの名前は `partype`（マナ・気・フューリー など）。`なし` のチャンピオンはリソースの行を出さない
   - Lv.n の値は `基礎 + 成長 × (n-1) × (0.7025 + 0.0175 × (n-1))`。攻撃速度は `基礎 × (1 + 成長% × 同じ係数 / 100)`
   - 移動速度・射程は成長が無いので Lv.1 の値だけ
5. スキル: パッシブと Q/W/E/R を、アイコン・キー・名前・CD・コスト・射程（`rangeBurn`）・説明文（要件1・2.5 の数値入り。解けなければ概要）で並べる
6. カードは開閉できる。最初は開いている
7. 価格（BE・RP）・実装日・最終更新は Data Dragon に無いため、今回は出さない
8. 狭い画面ではステータスの表を1列にする
